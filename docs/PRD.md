# [PRD] 링크트리 클론 서비스 "마이링크 (MYLINK)" 제품기능정의서

---

## 1. 프로젝트 개요 & 시연 전략 (Executive Summary)

* **제품명**: 마이링크 (MYLINK)
* **제품 정의**: 토스 디자인 시스템(TDS) 기반의 단정하고 직관적인 UX를 제공하며, 브라우저 **로컬스토리지(localStorage)**를 활용해 프로필과 링크 데이터를 동적으로 관리하고 보여주는 개인 전용 링크트리 웹 애플리케이션
* **시연(Demo) 전략 & 단계별 접근**:
  * 본 프로젝트는 단계별 시연을 목적으로 진행합니다.
  * 복잡한 대시보드, 지표 차트, 클릭수 통계 등은 초기 스코프에서 과감히 제외합니다.
  * **현재 단계(Phase 1)**의 핵심 목표는 **"로컬스토리지를 활용해 완전히 동적으로 동작하는 완성도 높은 프로필 페이지"**를 구축하는 것입니다.

## 2. 기능 범위 설정 (Scope Definition)

### ✅ 현재 구현 범위 (In-Scope : Phase 1 MVP)
1. **로컬스토리지 기반 데이터 모델링 & 영속화**:
   * 하드코딩된 정적 페이지가 아닌, 브라우저 `localStorage`에서 데이터를 읽어와 렌더링
   * 초기 접속 시 기본 프로필 데이터(`DEFAULT_PROFILE_DATA`) 자동 세팅
2. **토스 디자인 시스템 (TDS) UI**:
   * 토스 시그니처 블루 (`#3182F6`), 쿨 그레이 뉴트럴, Pretendard 웹폰트
   * 모바일 퍼스트 최적화 화면 (56px TopBar, 프로필 카드, 칩 필터, 리스트 로우, 하단 고정 CTA)
3. **인터랙티브 기능**:
   * 카테고리별 링크 필터링 (전체 / 소셜 & 기록 / 프로젝트 / 연락처)
   * 원클릭 이메일 복사 & 공유 URL 복사 토스트 피드백

### 🚫 제외 범위 (Out-of-Scope : 후속 단계로 연기)
* ❌ 방문자 클릭수 통계 및 분석 차트
* ❌ 복잡한 관리자 대시보드 및 지표 요약 위젯
* ❌ 외부 데이터베이스(DB) 및 백엔드 서버 연동

## 3. 사용자 시나리오 (User Scenarios)

### 3.1. 방문자 (Visitor) 관점
> **상황**: 인스타그램 프로필, 이력서, 포트폴리오 링크를 통해 다른 사람의 마이링크 페이지를 방문하여 정보를 탐색하고 연락하는 과정

* **1단계 (접속 및 진입)**: 사용자는 상대방의 프로필과 작업물을 한눈에 모아보기 위해 SNS 프로필이나 이력서에 기재된 **마이링크 URL을 클릭하여 메인 페이지(`/`)에 접속**한다.
* **2단계 (프로필 파악)**: 사용자는 이 페이지 소유자의 정체성과 주요 전문 분야를 빠르게 파악하기 위해 최상단 프로필 카드의 **이름, 직무, 소개글, 기술 스택 태그를 확인**한다.
* **3단계 (카테고리 탐색)**: 사용자는 자신이 관심 있는 콘텐츠(프로젝트, 블로그 글, 소셜 미디어 등)만 모아서 보기 위해 상단 필터 영역에서 **원하는 카테고리 칩('프로젝트', '소셜 & 기록' 등)을 클릭**한다.
* **4단계 (외부 링크 이동)**: 사용자는 소유자가 제작한 서비스나 작성한 개발 블로그 글을 직접 확인하기 위해 해당 **링크 아이템(GitHub, Velog 등)을 클릭하여 새 창으로 이동**한다.
* **5단계 (연락처 원클릭 복사)**: 사용자는 소유자에게 협업 또는 질문 메일을 보내기 위해 목록 내 이메일 항목을 클릭하여 **이메일 주소를 클립보드에 복사**한다. (상단 토스트 알림 확인)
* **6단계 (원스톱 커피챗 제안)**: 사용자는 소유자에게 가볍게 네트워킹이나 티타임을 제안하기 위해 화면 하단에 고정된 **'이메일로 커피챗 제안하기' CTA 버튼을 클릭**한다.
* **7단계 (프로필 공유)**: 사용자는 발견한 멋진 포트폴리오를 동료에게 전달하거나 나중에 다시 보기 위해 상단 탑바의 **공유 아이콘을 클릭하여 마이링크 링크를 복사**한다.

### 3.2. 소유자 (Owner) 관점
> **상황**: 자신의 마이링크에 새로운 링크를 등록하고, 기존 링크의 내용을 수정 및 삭제하여 최신 상태로 관리하는 과정

* **1단계 (관리자 페이지 접근)**: 사용자는 자신의 마이링크 프로필과 링크 정보를 편집하기 위해 주소창에 **관리자 경로(`/admin`)를 직접 입력하여 이동**한다.
* **2단계 (관리자 권한 잠금 해제)**: 사용자는 타인의 무단 수정을 방지하고 본인임을 인증하기 위해 화면에 나타난 **마스터 PIN(비밀번호)을 입력**한다.
* **3단계 (신규 링크 추가)**: 사용자는 최근 배포한 사이드 프로젝트를 내 마이링크에 새로 등록하기 위해 링크 관리 섹션의 **'새 링크 추가' 버튼을 클릭하고 제목, URL, 카테고리, 아이콘을 입력한 뒤 저장**한다.
* **4단계 (링크 정보 수정)**: 사용자는 기존에 등록해 둔 블로그 링크의 설명 문구를 더 매력적으로 변경하기 위해 해당 링크 옆의 **'수정(연필)' 아이콘을 클릭하고 텍스트를 고친 후 저장**한다.
* **5단계 (링크 노출 순서 변경)**: 사용자는 이번 주에 가장 강조하고 싶은 프로젝트 링크를 목록 최상단에 배치하기 위해 해당 링크 카드의 **드래그 핸들을 마우스로 잡고 위쪽으로 끌어올린다(Drag & Drop)**.
* **6단계 (오래된 링크 삭제)**: 사용자는 더 이상 운영하지 않는 이전 프로젝트 링크를 목록에서 지우기 위해 해당 링크의 **'삭제(휴지통)' 버튼을 클릭하고 확인 팝업에서 승인**한다.
* **7단계 (실시간 모바일 뷰어 확인)**: 사용자는 자신이 수정한 링크와 순서가 모바일 화면에서 자연스럽게 배치되었는지 확인하기 위해 우측 **실시간 스마트폰 미리보기 뷰어를 확인**한다.
* **8단계 (최종 공개 화면 검토)**: 사용자는 일반 방문자에게 보여질 실제 페이지를 최종 점검하기 위해 상단 탑바의 **'내 링크 바로가기' 버튼을 클릭하여 메인 프로필 페이지(`/`)로 이동**한다.

## 5. 데이터 스키마 (Data Schema)

로컬스토리지 키: `mylink_profile_data`

```typescript
// 링크 아이템 인터페이스
export interface LinkItem {
  id: string;                      // 고유 식별자 (예: 'github', 'velog')
  category: "all" | "social" | "project" | "contact";
  title: string;                   // 링크 제목
  subtitle: string;                // 부가 설명
  url: string;                     // 이동할 URL
  badge?: string;                  // 선택적 뱃지 (예: '업데이트', 'v2.0')
  iconType: "github" | "velog" | "project" | "instagram" | "email";
  isCopyAction?: boolean;          // 클릭 시 주소 복사 동작 여부
}

// 전체 프로필 데이터 인터페이스
export interface ProfileData {
  name: string;                    // 표시 이름 (예: 박다정)
  role: string;                    // 직무 (예: Frontend Developer)
  bio: string;                     // 소개 문구
  avatarText: string;              // 아바타 텍스트/이니셜 (예: 다정)
  statusBadge: string;             // 상태 뱃지 문구 (예: 커피챗 환영)
  techStack: string[];             // 기술 스택 목록
  primaryCtaText: string;          // 하단 고정 CTA 버튼 문구
  primaryCtaUrl: string;           // 하단 고정 CTA URL
  links: LinkItem[];               // 등록된 링크 목록
}
```

## 6. 단계별 개발 로드맵 (Demonstration Roadmap)

* **📌 Phase 1 (현재 단계 — MVP 프로필 페이지)**:
  * 로컬스토리지(`localStorage`) 기반 데이터 스토리지 연동
  * 토스 디자인 시스템(TDS) 스타일의 모바일 최적화 프로필 페이지 완성
  * 통계/대시보드 없이 깔끔하고 빠른 시연 환경 구축
* **Phase 2 (차후 단계 — 에디터 도입)**:
  * 로컬스토리지 데이터를 직접 수정할 수 있는 심플한 편집 모드/페이지
  * 링크 추가, 수정, 삭제, 순서 변경
* **Phase 3 (고도화 단계 — 옵션)**:
  * JSON 내보내기/가져오기 백업 기능
  * 단순 PIN 잠금 및 관리자 권한 보호
